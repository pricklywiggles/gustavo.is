## Framework & rendering

- Next.js 16.2.10, App Router, Turbopack for dev and build. `next.config.mjs` must stay `.mjs` (fumadocs-mdx needs the ESM file) and is wrapped `withSentryConfig(withBotId(withMDX(config)))`. Edits to it need a dev-server restart; Turbopack hot reload does not cover it. Turbopack also serves stale builds at times: `rm -rf .next` and restart when CSS or tokens look wrong, after checking for another server or an orphaned task holding the port. Never set `output: "export"` (it disables Route Handlers) and never enable SPA fallback routing (it returns 200 for unmatched paths and kills real 404s). `cacheComponents` is off; plain static is already right for this content.
- React 19.2.7, `react-dom` matching. Well past the React2Shell RSC fix (19.2.1+).
- The intro's transparent scene ships as two files, because no engine plays both alpha formats: `public/scene_home.webm` (VP9 alpha, 479 KB) for Chromium and Firefox, `public/scene_home.mov` (HEVC alpha, 1.8 MB) for WebKit. `intro.tsx` sets `src` on mount, WebKit detected by `webkitPresentationMode` on the element, and the server markup names no file at all. Two facts force that shape: Firefox on macOS answers "probably" to a QuickTime HEVC `<source>` through the system decoder, so a source list makes it download the whole `.mov` at parse time (in full, despite `preload="metadata"`) and then paint it opaque; and a file named in the markup is fetched before any effect runs. Deciding after hydration costs nothing visible (the scene is below the fold and scroll-cued); without JS there is no decorative video. Encode the `.mov` on a Mac through Apple's exporter, since real Safari paints ffmpeg's `hevc_videotoolbox` alpha opaque even though Playwright's WebKit renders it: `ffmpeg -c:v libvpx-vp9 -i public/scene_home.webm -c:v prores_ks -pix_fmt yuva444p10le -profile:v 4444 -alpha_bits 16 -an /tmp/scene.mov` (libvpx keeps the alpha plane), then `avconvert --preset PresetHEVCHighestQualityWithAlpha --source /tmp/scene.mov --output public/scene_home.mov --replace`.
- Images go through `next/image` with the Vercel loader; `remotePatterns` allows `i.ytimg.com/vi/**` for the blog's YouTube cards. The Hobby quota is 5,000 transformations a month, counted per source image, and it stops rather than bills when exceeded.

## Animation

- Motion 12.42.2 handles component-level animation. Import from `motion/react`, never `framer-motion`. `LazyMotion` with `m` components keeps the bundle small (about 4.6KB plus the feature set); a full `motion` component throws inside the `strict` LazyMotion provider.
- Motion+ (`motion-plus` 2.12.0, aliased to `@motionplus/core` from the private `api.motion.dev/npm` registry) supplies `Ticker` (the retrospective tech band), `AnimateNumber` (the landing year readout), and `curtains` and `blinds` (the `CurtainLink` page transitions). Imports are `motion-plus/react` and `motion-plus/curtains`. Vercel and CI installs need `MOTION_TOKEN` or they 401.
- GSAP 3.15.0 with ScrollTrigger does scroll-driven pinning and scrubbing only, the one thing Motion cannot. Never animate the same property of the same element with both libraries; assign ownership per element. `@gsap/react` 2.1.2 provides `useGSAP()`; it is feature-complete rather than abandoned and verified compatible with React 19. Never write a `useGSAP` call whose dependency array changes length between renders.
- The two-library rule has a sharp edge worth stating on its own: a GSAP scale anywhere above a Motion or Motion+ animated node breaks it silently. `AnimateNumber` computes reel travel from transform-inclusive rects, so an ancestor scale sends the digits the wrong distance while every settled rect still measures correct. Scale a static stand-in and dock it onto the animated node instead. Verify animation by watching it, never by reading geometry back.
- Reduced motion is an accessibility obligation here (WCAG 2.2 AA target). Read it through `useReducedMotionLive` (`src/components/use-reduced-motion-live.ts`), which is mount-gated and live; Motion's own `useReducedMotion` returns true on a reduced client's first render, so branching SSR-visible DOM on it ships the wrong markup. GSAP uses `gsap.matchMedia()`. There is no app-wide `MotionConfig reducedMotion="user"`. Test the reduced path with a Playwright context of `{ reducedMotion: "reduce" }`; jsdom's `matchMedia` polyfill answers `matches: false`, so unit tests exercise the motion-enabled branch unless the hook is mocked.
- iOS is its own code path. `isIOSDevice()` (`src/lib/ios-device.ts`) is the only gate: it needs `maxTouchPoints > 0` plus an iOS user agent, and it treats the Macintosh UA that iPadOS 13+ sends as iOS when the touch count is above one. Never gate an iOS fix on a media query, and never degrade desktop or Android to fix iOS. Chrome on iOS runs Safari's engine and takes the same branch. `src/lib/scroll-scrub.ts` holds the shared scrub smoothing.
- The landing scroll story is the largest animation surface in the repo and has its own architecture doc with the invariants and the already-paid-for pitfalls: read `src/components/landing/README.md` before changing anything under `src/components/landing/`.

## Security & ops

- Security headers come from `headers()` in `next.config.mjs`: CSP, HSTS (production only, since Safari caches it from localhost and then force-upgrades dev), nosniff, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, a Permissions-Policy, plus `poweredByHeader: false`. Read the file's comments before changing any of it.
- CSP: `script-src 'self' 'unsafe-inline'` is a recorded decision. Next streams RSC hydration through per-page inline scripts that cannot be hash-allowlisted, and a nonce needs dynamic rendering site-wide; a stricter value silently stops hydration while the page still looks right. Accepted because nothing renders visitor content as raw HTML; revisit if that ever changes. `'unsafe-eval'` is added in dev only (React dev tooling). `style-src` needs `'unsafe-inline'` for the component ecosystem. `frame-src https://player.vimeo.com` exists solely for the retrospective walkthrough embeds. `upgrade-insecure-requests` is production only (WebKit applies it to localhost). After any CSP change, confirm hydration in a real browser, not just that the headers are present.
- Sentry (`@sentry/nextjs`) 10.70.0. Errors only: `tracesSampleRate: 0`, no replay, no logs, `sendDefaultPii: false`. Server and edge init in `src/instrumentation.ts` (`onRequestError` catches SSR and route-handler 500s), browser init in `src/instrumentation-client.ts` (with `onRouterTransitionStart`), and both error boundaries (`error.tsx`, `global-error.tsx`) call `captureException`. Without `NEXT_PUBLIC_SENTRY_DSN` the SDK stays disabled; `SENTRY_ORG`, `SENTRY_PROJECT` and `SENTRY_AUTH_TOKEN` only gate source-map upload at build. Events ride the same-origin `tunnelRoute: "/sentry-tunnel"`, so no CSP `connect-src` carve-out is needed. The environment tag is `VERCEL_ENV` on the server and `NEXT_PUBLIC_VERCEL_ENV` in the browser, falling back to `NODE_ENV`. Verified end to end from a preview: a browser error reached the `gustavo-is` project through the tunnel, and source-map artifact bundles upload on every build (the Vercel log says nothing about it; check the project's artifact bundles). Neither init gates on the environment, so a DSN in `.env.local` turns every hot-reload hiccup into an issue.
- Secrets are Vercel Sensitive Environment Variables mirrored into `.env.local`. Never prefix a secret with `NEXT_PUBLIC_`: those inline into the client bundle at build. "Enable access to System Environment Variables" must stay on for the project, or `NEXT_PUBLIC_VERCEL_ENV` is undefined in every build, `isProductionDeploy()` is always false, and both analytics products stay dark in production while Sentry tags previews as `production`.
- Cache headers need no config: Next content-hashes `/_next/static/*` and Vercel serves it immutable for a year.
