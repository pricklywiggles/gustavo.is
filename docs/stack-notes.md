## Runtime & tooling

- Node.js 24.x, pinned by `engines` and `.nvmrc`. Vercel offers only 20.x, 22.x and 24.x, so never rely on a newer local Node. Corepack still ships with Node 24, which is what lets Vercel honor `packageManager`, but only with `ENABLE_EXPERIMENTAL_COREPACK=1` set on the project; without it Vercel falls back to pnpm 6.
- pnpm 11.11.0, pinned by `packageManager`. The project switched from npm mid-pipeline via `pnpm import`, so the `npm install <pkg>` lines in the lockfile's `install:` steps are historical records of the original installs, not the reproduction path. Add with `pnpm add <pkg>@<version> --save-exact`. Trailing script args pass straight through (`pnpm run dev -p 4200`); npm's `--` separator hands Next a literal `-p` as its project directory.
- Supply chain lives in `pnpm-workspace.yaml`, not `.npmrc` and not `package.json`: `minimumReleaseAge: 10080` (a 7-day cooldown, stricter than pnpm's 24h default), `allowBuilds` as the install-script allowlist (`sharp`, `esbuild`, `fsevents`; `@sentry/cli` is deliberately `false` because its postinstall only duplicates the platform binary the optional dependency provides), and `overrides` pinning `@babel/core` to 7.29.7 (`@vitejs/plugin-react`'s optional Babel 8 plugin conflicted with shadcn's Babel 7 toolchain). pnpm v11 replaced `onlyBuiltDependencies` with the `allowBuilds` map and reads no `overrides` from `package.json`. `.npmrc` carries the same 7-day cooldown in npm's dialect plus the `@motionplus` registry URL; the auth token stays out of the repo (user-level npm config locally, `MOTION_TOKEN` on Vercel). Provenance attestations are not a malware check. Never enable dependency auto-merge; with a cooldown it just merges later.
- TypeScript 6.0.3: 7.x has no stable programmatic API yet, so compiler-API consumers cannot use it; revisit at 7.1. `@/*` maps to `src/*`. `react-canary.d.ts` declares the canary exports (`ViewTransition`, `addTransitionType`) that the App Router's bundled React has and the installed `react` package lacks; vitest never sees them.
- Biome 2.5.3 (`biome.json`): lint and format in one tool, replacing `next lint` (removed in Next 16; `next build` no longer lints and Vercel builds do not gate on lint). Tabs, double quotes, react and next domains on recommended, `css.parser.tailwindDirectives: true` so `globals.css` parses, `public/` and `.impeccable/` excluded, organize-imports on. Run `pnpm run check` before pushing; nothing else enforces it.

## Framework & rendering

## Animation

- Motion 12.42.2 handles component-level animation. Import from `motion/react`, never `framer-motion`. `LazyMotion` with `m` components keeps the bundle small (about 4.6KB plus the feature set); a full `motion` component throws inside the `strict` LazyMotion provider. `useReducedMotion` is truthy on a reduced client's first render, so never branch SSR-visible DOM on it; mount-gate instead.
- Motion+ (`motion-plus` 2.12.0, aliased to `@motionplus/core` from the private `api.motion.dev/npm` registry) supplies `Ticker` (the retrospective tech band), `AnimateNumber` (the landing counter), and `curtains` and `blinds` (the `CurtainLink` page transitions). Imports are `motion-plus/react` and `motion-plus/curtains`. Vercel installs need `MOTION_TOKEN` or they 401.
- GSAP 3.15.0 with ScrollTrigger does scroll-driven pinning and scrubbing only, the one thing Motion cannot. Never animate the same property of the same element with both libraries; assign ownership per element. `@gsap/react` 2.1.2 provides `useGSAP()`; it is feature-complete rather than abandoned and verified compatible with React 19. Never write a `useGSAP` call whose dependency array changes length between renders.
- Reduced motion is an accessibility obligation here (WCAG 2.2 AA target) and is handled per component: `useReducedMotion` (mount-gated) on the Motion side, `gsap.matchMedia()` on the GSAP side. There is no app-wide `MotionConfig reducedMotion="user"`.

## Security & ops

- Security headers come from `headers()` in `next.config.mjs`: CSP, HSTS (production only, since Safari caches it from localhost and then force-upgrades dev), nosniff, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, a Permissions-Policy, plus `poweredByHeader: false`. Read the file's comments before changing any of it.
- CSP: `script-src 'self' 'unsafe-inline'` is a recorded decision. Next streams RSC hydration through per-page inline scripts that cannot be hash-allowlisted, and a nonce needs dynamic rendering site-wide; a stricter value silently stops hydration while the page still looks right. Accepted because nothing renders visitor content as raw HTML; revisit if that ever changes. `'unsafe-eval'` is added in dev only (React dev tooling). `style-src` needs `'unsafe-inline'` for the component ecosystem. `frame-src https://player.vimeo.com` exists solely for the retrospective walkthrough embeds. `upgrade-insecure-requests` is production only (WebKit applies it to localhost). After any CSP change, confirm hydration in a real browser, not just that the headers are present.
- Sentry (`@sentry/nextjs`) 10.70.0. Errors only: `tracesSampleRate: 0`, no replay, no logs, `sendDefaultPii: false`. Server and edge init in `src/instrumentation.ts` (`onRequestError` catches SSR and route-handler 500s), browser init in `src/instrumentation-client.ts` (with `onRouterTransitionStart`), and both error boundaries (`error.tsx`, `global-error.tsx`) call `captureException`. Without `NEXT_PUBLIC_SENTRY_DSN` the SDK stays disabled; `SENTRY_ORG`, `SENTRY_PROJECT` and `SENTRY_AUTH_TOKEN` only gate source-map upload at build. Events ride the same-origin `tunnelRoute: "/sentry-tunnel"`, so no CSP `connect-src` carve-out is needed. The environment tag is `VERCEL_ENV` on the server and `NEXT_PUBLIC_VERCEL_ENV` in the browser, falling back to `NODE_ENV`.
- Secrets are Vercel Sensitive Environment Variables mirrored into `.env.local`. Never prefix a secret with `NEXT_PUBLIC_`: those inline into the client bundle at build.
- Cache headers need no config: Next content-hashes `/_next/static/*` and Vercel serves it immutable for a year.

## Analytics

- Plausible Community Edition 3.2.1 at `metrics.whpl.sh`, managed outside this repo (the in-repo compose recipe was dropped on 2026-08-26), reached through `@plausible-analytics/tracker` 0.4.6. `initAnalytics()` in `src/lib/analytics.ts` runs from `src/instrumentation-client.ts` and is inert unless `NEXT_PUBLIC_VERCEL_ENV` is `production`, so dev and previews never report as `gustavo.is`. Events post to the same-origin `/api/pa`, rewritten to the instance in `vercel.json` (`next dev` ignores that file; the tracker is inert there anyway). The rewrite path avoids the words analytics, stats and plausible on purpose, since ad blockers match on them, and the rewrite satisfies the `X-Forwarded-For` requirement a custom proxy would not. Cookieless, so no consent banner for a US operator.
- Tracked: pageviews, scroll depth, engagement time, outbound-link clicks (`Outbound Link: Click`), and the custom events in `EVENTS`: `Contact: Opened`, `Contact: Sent`, `Contact: Failed` (prop `source`: `intro`, `landfall`, `header`, `page`; failed adds `status`), `Video: Played` (`video`), `404` (`path`). Every event carries `motion: reduced | full`. A custom event only shows once a matching custom-event goal exists in the Plausible site settings; nothing is backfilled. Keep props low-cardinality and never put visitor input in them. `track()` is a no-op until init ran and swallows tracker errors.
- CE has goals, custom props, scroll-depth goals and the Stats API, but not funnels, user journeys, ecommerce revenue goals, the Sites API, or advanced bot filtering: read opened-to-sent as two goal counts. Exclude your own browser with `localStorage.plausible_ignore = "true"`. CE patches are not backported to older minors, so keep the instance current.
- Vercel Speed Insights 2.0.0: `<SpeedInsights />` in `src/app/layout.tsx`, rendered on production deploys only. In dev it would load from `va.vercel-scripts.com`, which the CSP blocks, and previews would spend the Hobby quota (10k events/month, 7-day window; past the cap, recording pauses until the next day). It also needs enabling per project in the Vercel dashboard.

## Platform

- Vercel, Hobby plan; the ToS risk of a portfolio on a non-commercial plan is accepted by the owner. Git-push builds are the CI; nothing else gates a deploy. Two project env vars are required before any deploy works: `ENABLE_EXPERIMENTAL_COREPACK=1` and `MOTION_TOKEN`. Hobby limits that matter: one concurrent build, a 60s function ceiling, and no Log Drains (part of why Sentry earns its place).
- DNS and TLS are on Vercel. Resend's SPF, DKIM and MX records go on the sending subdomain, with DMARC starting at `p=none`. Domain expiry is the likeliest way the site dies: keep auto-renew, a live payment method, and MFA on the registrar, Vercel and GitHub accounts.
- The writing is the only irreplaceable asset: mirror the repo to a second git host and back up the Plausible databases separately.
